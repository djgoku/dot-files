#+TITLE: dot-files
#+AUTHOR: djgoku

* Overview

Personal macOS development environment. [[https://mise.jdx.dev/][mise]] is the only entry point: it
installs every tool, applies dotfiles, and configures the machine through
=mise bootstrap=. There is no Nix. The root =mise.toml= contains project checks
and tasks; machine configuration lives in =config/mise/=.

* Quick Start

Prerequisites: macOS, Xcode CLI tools (=xcode-select --install=).

#+begin_src sh
curl -fsSL https://raw.githubusercontent.com/djgoku/dot-files/main/setup.sh | zsh
#+end_src

Or clone and run locally:

#+begin_src sh
mkdir -p ~/dev/github/djgoku && cd "$_"
git clone https://github.com/djgoku/dot-files.git
cd dot-files && ./setup.sh
#+end_src

=setup.sh= does only what cannot be declared in config: clone the repo and
install or update mise. It then points mise at the config inside the clone with
=MISE_CONFIG_DIR= and lets mise create =~/.dot-files= and =~/.config/mise=
from its own =[dotfiles]= entries -- no path is symlinked by hand -- before
running =mise bootstrap --yes=. It takes =--no-clone= (use the checkout
already in place) and =--prepare-only= (stop before bootstrapping); CI uses
both rather than reimplementing the setup.
Once bootstrapped, re-apply at any time with:

#+begin_src sh
mise bootstrap --yes
#+end_src

** Why =config/mise/= and not =mise/=

mise auto-discovers =mise/config.toml=, =.mise/conf.d/=, and
=.config/mise/conf.d/= as /project/ config. Any of those names would mean that
=cd=-ing into this repo loads the machine config a second time -- including its
=[bootstrap]= stanzas, so =[bootstrap.macos.defaults]= would go live locally.
=config/mise/= matches no discovery rule, so the =~/.config/mise= symlink is
the only path by which it loads.

* Bootstrap Order

=mise bootstrap= applies files, repos, dotfiles, and macOS settings before it
installs versioned tools. Anything that shells out to an installed binary must
run in =post-tools= or =final=. Two entries here depend on that ordering:

- =~/.gnupg/gpg-agent.conf= interpolates =mise which pinentry-curses=. It
  renders at the dotfiles stage with a bare-name fallback so the stage cannot
  hard-fail, then =post-tools= re-renders it with the resolved absolute path.
- The gpg-agent restart runs in =post-tools=, where =gpgconf= actually exists.

Inspect without changing anything:

#+begin_src sh
mise bootstrap --dry-run
#+end_src

Run a single stage:

#+begin_src sh
mise bootstrap --only files --yes
#+end_src

Note that =bootstrap.directories= is applied as part of the =files= stage;
there is no =--only directories=. Mise creates missing parent directories with
OS default permissions. Parents that need a specific mode are declared
explicitly in =conf.d/20-files.toml=.

* CI

GitHub Actions, in two tiers:

- *Validate* runs on every push and PR. It installs only project tools; it runs
  =hk check --all=, asserts the five tracked machine config files load, checks
  every bootstrap stage under =--dry-run=, confirms Packslip Emacs is
  discoverable, and checks generated workflow YAML against its Pkl source.
- *Bootstrap* runs weekly and on =workflow_dispatch=. It runs =setup.sh= for
  real on a clean macOS runner, asserts the artifacts, and re-runs bootstrap to
  check that repeated application succeeds.

** Workflow YAML is generated -- do not hand-edit it

=.github/workflows/*.yml= is rendered from the =.pkl= file beside it using
[[https://pkl-lang.org/][Pkl]] and the =com.github.actions= pkl-pantry package.
Edit the =.pkl=, then:

#+begin_src sh
mise run render-workflows
#+end_src

The validate job runs this task through hk. =mise run check-workflows= renders
to a temporary directory and compares each =.yml= with its Pkl source. It
leaves the checkout unchanged, so it also works before changes are committed.

Note this repo carries two mise configs with different jobs: =mise.toml= at the
root is *project* config (tasks, hk, Pkl, and Tombi), while =config/mise/=
is *machine* config and is not discovered from the repo as project config.

** Repository checks

Run all project checks through mise:

#+begin_src sh
mise exec -- hk check --all
#+end_src

=hk.pkl= checks TOML lint and formatting with Tombi, Pkl formatting and
workflow evaluation/YAML drift, and =setup.sh= syntax with =zsh -n=.
=hk fix --all= applies available formatting
fixes without staging them. To run the same checks before local commits, use
=mise exec -- hk install --mise= once in this checkout. This installs a local
Git hook; it does not change global Git settings.
Remove it with =mise exec -- hk uninstall= if you no longer want it.
The local launcher requires =mise= on Git's =PATH= when a commit runs.

The machine tool lockfile is global. Refresh it with =mise lock --global=;
=lockfile_platforms= includes Linux and macOS targets and excludes Windows.

After changing =.github/PklProject=, re-resolve and commit the lockfile:

#+begin_src sh
pkl project resolve .github/
#+end_src

Note pkl does *not* discover a =PklProject= in an ancestor directory, which is
why the render task passes =--project-dir .github/=.

* Caveats

- =macos-defaults= writes to your *real* macOS preferences. A sandboxed =HOME=
  does not isolate them, because =cfprefsd= is keyed by uid. Use =--dry-run=
  to inspect.
- =com.apple.Terminal.plist= is applied with =mode = "copy"=, not =symlink=,
  because =cfprefsd= rewrites the file in place. Quit Terminal before applying
  or it will overwrite the copy again on quit.
- =bootstrap.repos= entries have no =ref=, so mise never pulls -- an existing
  clone with a matching origin counts as current. A dirty worktree fails the
  stage, so hide local additions with =.git/info/exclude=.

#+begin_src sh

#+end_src
